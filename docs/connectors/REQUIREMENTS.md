# 커넥터 현대화 요구사항

상태: 2026-09-29. **검토 단계.** 결정 체크리스트([DESIGN](./DESIGN.md))가 닫히기 전에는 코드를 고치지 않는다.

## 요구

- **R-CN-01 / 커넥터 5종을 각 프레임워크의 최신 버전에 맞춘다.** 사용자: "이번이 어차피 대규모 수정이라 프레임워크별 커넥터도 올바른 방식으로 개선하고 싶다. 최신 버전에 맞추고 그 프레임워크가 권장하는 API를 쓰고 싶다. 예를 들어 React는 `useSyncExternalStore`를 쓰라고 한다."
- **R-CN-02 / 각 프레임워크가 외부 상태 연결에 권장하는 API를 쓴다.** 권장 API가 무엇인지는 [DESIGN](./DESIGN.md)의 프레임워크별 절에 근거와 함께 적는다.
- **R-CN-03 / 검토부터 한다.** 사용자는 "검토해봐"라고 했다. 이 문서 세트가 그 결과이고, 구현은 사용자가 결정 항목을 고른 뒤 시작한다.

## 제약

- **C-CN-01 / 공개 API 모양은 가능한 한 지킨다.** `connectX(watch)`와 `connectXView(watch)`의 호출 모양, 반환 모양(React·Preact: 훅, Vue: `Reactive<{ value }>`, Svelte: store, Solid: `Signal`)은 이 저장소의 예제 5종·문서 사이트·패키지 README가 인용한다. 바꾸면 breaking이고, 버전·문서·예제를 함께 옮겨야 한다([DC-CN-02](./DESIGN.md)).
- **C-CN-02 / 의존성 추적 모델을 바꾸지 않는다.** 코어는 "`watch(renew)`가 돌려준 ref로 `.value`를 읽는 순간 그 경로가 구독에 들어간다"는 모델이다(`packages/state-ref/src/connectors/collector.ts`). 컴포넌트가 렌더에서 읽은 필드만 다시 그리게 하는 것이 이 라이브러리의 장점이고, 커넥터는 이 모델 위에서 프레임워크 규칙을 지켜야 한다.
- **C-CN-03 / 기존 커넥터 테스트(React 7 · Preact 5 · Vue 33 · Svelte 35 · Solid 13 파일)와 e2e 84개를 기준선으로 둔다.** 버그 기록 `CI-25`·`CI-26`·`CI-29`(Vue), 구독 해제(IC-01), SSR 누수 방지가 그 테스트에 있다. 새 구현은 이것들을 모두 통과해야 한다.
- **C-CN-04 / 동등성·무부작용을 주장하지 않는다.** 상시 결정.

## 합격 기준

- 각 커넥터의 peer 범위가 [DC-CN-01](./DESIGN.md)이 정한 버전을 받고, 그 **최소·최신 버전 양쪽**에서 커넥터 테스트가 통과한다.
- React StrictMode에서 값이 늦게 보이는 결함([DESIGN](./DESIGN.md) F-R1)이 회귀 테스트로 고정되고 통과한다.
- `pnpm gate` 19단계와 `pnpm test:e2e` 84개가 통과한다.
- 커넥터 문서(사이트의 Framework Integration 6장 en+ko, 패키지 README)가 새 버전 범위와 바뀐 동작을 적는다.
