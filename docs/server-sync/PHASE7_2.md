# Phase 7.2 — 독립 참조 모델 비교

**진입:** Phase 7.1의 순서·경계 반례와 전체 gate 통과.
**범위:** Phase 7 항목 2의 작업 실패 후 잔여 intent와 두 기준 값의 모델 대조.
**종료:** 결과 행렬 전수 대조, 발견한 정확성 결함 0 또는 수정, 모델의 검증력 확인, 전체 gate 통과.

## 요구와 결정

- [x] **DC7-2-01 / 모델 독립성:** 참조 모델은 계약에서 직접 작성하고 구현의 정규화·병합·변경 추적 코드를 재사용하지 않는다([IMPLEMENT](./IMPLEMENT.md)의 원칙). 모델은 서버 기준·로컬 값·미확정 표시만 들고, 잔여 intent는 두 값의 차이로 계산한다.
- [x] **DC7-2-02 / 대조 축:** 수용 방식(`none`/`submitted`/`refetch`), 결과(`success`/`rejected`/`unknown`/`sync-error`), 거절 정책(`keep`/`remove`), 전송 중 후속 입력 유무, 복구 수단(없음/재조회/`acceptServer`)의 전수 조합을 대조한다. 각 조합에서 로컬 값·dirty·미확정을 함께 비교한다.
- [x] **DC7-2-03 / 제출된 입력의 소멸:** `refetch` 수용은 제출한 입력을 **소비**한다. 서버가 이미 반영했으므로 재조회 기준이 제출 경로를 덮고, **제출하지 않은** 후속 입력만 기준보다 우선한다. [Phase 7.1](./PHASE7_1.md)의 "로컬 입력 우선"은 미제출 입력에만 적용된다.
- [x] **DC7-2-04 / 실패의 잔여 intent:** `unknown`과 `sync-error`는 모두 미확정으로 두고 입력을 보존한다. 확정 거절은 `remove` 정책일 때만 제출 입력을 되돌린다. 재조회나 `acceptServer`로 확정 기준을 얻으면 미확정이 해소되고 소비되지 않은 입력은 새 기준 위에 남는다.
- [x] **DC7-2-05 / 차이:** 모델은 한 resource의 한 단계 필드만 다루며 여러 query·무한 조회·영속화는 범위 밖이다. 수명 반복·메모리와 타입 negative·배포 검사는 Phase 7의 남은 하위 범위다.

## 구현 단계와 기준 테스트

1. **모델:** 서버 기준·로컬 값·미확정과 결과별 전이를 계약에서 작성한다. **기준 테스트:** 결과 행렬 전수 대조에서 불일치 0건.
2. **복구:** 재조회·`acceptServer` 전이를 더한다. **기준 테스트:** 미확정 해소와 잔여 intent 보존.
3. **검증력:** 모델과 구현 양쪽을 흔들어 대조가 살아 있는지 본다. **기준 테스트:** 잘못된 모델 규칙이 구현과 불일치함을 명시, 구현 결함 주입 3종이 모두 불일치로 잡힘.
4. **통합:** sync 회귀와 `pnpm gate`; canonical 문서와 인계를 갱신한다.

## 인계

- done: 144개 조합(수용 3 × 결과 4 × 거절 정책 2 × 후속 입력 2 × 복구 3)을 독립 모델과 전수 대조했다. **발견한 정확성 결함은 0건**이고 구현 변경도 없다. 대신 처음 작성한 모델이 틀렸고 그 지점이 이 단계의 소득이다: `refetch` 수용은 제출한 입력을 소비하므로 재조회 기준이 제출 경로를 덮고 미제출 후속 입력만 살아남는다. 모델을 고친 뒤 전 조합이 일치한다. 대조가 살아 있음을 양방향으로 확인했다 — 잘못된 모델 규칙은 구현과 불일치하고, 구현 결함 3종(거절 정책 무시, `sync-error`의 미확정 미표시, `refetch`가 제출을 소비하지 않음)은 모두 불일치로 잡힌다. sync 런타임 **168개 테스트 PASS**, `pnpm gate` **PASS**.
