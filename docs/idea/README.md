# state-ref 아이디어

제품 방향과 기능 후보를 기록하는 디렉토리다. 이곳의 제안은 확정된 로드맵이나 현재 제공되는 API가 아니다. 채택할 아이디어는 별도의 요구사항과 설계 문서로 구체화한다.

## 제안 목록

| 문서 | 작성일 | 상태 | 핵심 방향 |
|---|---|---|---|
| [ref 기반 편집 기능과 차별화 방향](./editable-state.md) | 2026-09-18 | 검토 후보 | 아무 ref나 저장·취소 가능한 편집 대상으로 만들고, 입력 컴포넌트와 일괄 편집으로 확장 |

## 첫 번째 논의의 추천 방향

state-ref의 경로 기반 참조와 불변 갱신을 활용해 폼·관리자 화면·에디터에서 반복되는 편집 작업을 줄인다.

| ID | 아이디어 | 역할 |
|---|---|---|
| IDEA-01 | 저장·취소 가능한 편집 세션 | 대표 기능 후보 |
| IDEA-02 | ref 하나로 연결하는 입력 컴포넌트 | 편리함을 바로 보여주는 사용 경험 |
| IDEA-03 | 여러 항목을 하나의 필드처럼 편집 | 일괄 편집 데모의 핵심 |
| IDEA-04 | 하위 ref에 붙이는 undo/redo | 편집 기능의 확장 |
| IDEA-05 | 요청별 변경만 되돌리는 낙관적 업데이트 | 변경 기록과 충돌 처리 이후의 확장 |
| IDEA-06 | ID를 따라가는 배열 항목 ref | 동적 목록 편집을 위한 기반 |

우선 검토할 조합은 IDEA-01 + IDEA-02 + IDEA-03이다. 비교 근거, 제안 API, 구현 과제와 데모 시나리오는 [상세 문서](./editable-state.md)에 정리한다.

## 구현 설계로 구체화한 주제

[서버 상태 동기화](../server-sync/README.md)는 별도의 요구사항·설계·구현 계획·수동 검증 문서로 정리했다. resource가 데이터를 관리하는 방식을 선택했고, `target`은 제외했다. 공개 draft는 후속 확장이므로 이 아이디어 문서의 추천 순서와 서버 동기화의 구현 순서를 구분한다.
