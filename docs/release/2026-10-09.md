# 2026-10-09 배포 절차 — `@stateref/sync` 0.3.0, 커넥터 `./sync`, `@stateref/connect-lithent` 0.1.0

`claude/sync-query-hooks` 브랜치(컴포넌트가 소유하는 sync query: `client.observe`, 다섯 커넥터의 `./sync` 진입점, 새 `@stateref/connect-lithent`)를 `main`에 병합하고 패키지 7개를 올린다. 이 문서의 명령을 위에서부터 차례로 실행한다. 전체 흐름과 문제 대처는 [2026-09-30 배포 절차](./2026-09-30.md), [2026-10-08 배포 절차](./2026-10-08.md)와 같고, 여기서는 이번에 달라지는 부분만 적는다.

배포 기록: **준비만 했고 아직 실행하지 않았다(2026-10-09).** 실행하면 병합 커밋, 게시한 버전, 태그, GitHub 릴리스, `gh-pages` 커밋을 여기에 적는다.

준비 상태(병합 전 브랜치 기준):

- 버전: `@stateref/sync` 0.2.0 → **0.3.0**, `connect-react` 19.0.0 → **19.1.0**, `connect-preact` 10.4.0 → **10.5.0**, `connect-vue` 3.4.0 → **3.5.0**, `connect-solid` 1.4.0 → **1.5.0**, `connect-svelte` 5.0.0 → **5.1.0**, 새 `packages/connect-lithent` **0.1.0**. 커넥터 6종의 `peerDependencies`에 `@stateref/sync ^0.3.0`을 넣고 `peerDependenciesMeta`에서 선택 사항으로 표시했다.
- `CHANGELOG.md`에 `@stateref/sync 0.3.0`, `@stateref/connect-lithent 0.1.0`, 다섯 커넥터를 묶은 절을 넣었다.
- 패키지 README, 문서 사이트(영·한), AI 스킬에 컴포넌트 조회를 기본 경로로 적었다([sync-query-hooks IMPLEMENT](../sync-query-hooks/IMPLEMENT.md) 단계 7).
- 단계 6 기준 브랜치에서 `pnpm gate`(21단계), `pnpm check:examples`, 커넥터 매트릭스 19셀, `pnpm test:mission`(65개)이 통과했다. 문서 단계 뒤의 결과는 1절에서 다시 확인한다.

## 버전을 이렇게 정한 이유

- `@stateref/sync` **0.3.0**: `client.observe`가 추가됐고, 아래의 세 변경이 0.2.0에서 되던 코드를 깰 수 있다. 0.x에서는 minor가 깨지는 변경을 담는다. `^0.2.0` 범위는 0.3.0을 받지 않으므로 기존 설치가 저절로 올라가지 않는다.
- 다섯 커넥터는 **minor**: major는 프레임워크를 따르고(React 19, Preact 10, Vue 3, Solid 1, Svelte 5), 이번 변경은 하위 경로 `./sync`와 선택적 peer의 추가라 하위 호환이다. Preact·Vue·Solid·Svelte의 기본 진입점은 지난 배포와 같다. connect-react 19.1.0에는 19.0.0 배포 뒤 `main`에 병합된 PR #16(concurrent 마운트 중 쓰기의 tearing 수정, `d38956d`)이 함께 들어간다.
- 선택적 peer `@stateref/sync ^0.3.0`: `client.observe`가 처음 들어간 sync 버전부터 적는다(DC-QH-20). 기본 진입점만 쓰는 사람에게는 설치 요구가 없다. sync의 0.x minor마다 커넥터의 peer 범위를 넓혀 함께 올린다.
- `@stateref/connect-lithent` **0.1.0**: 첫 배포(DC-QH-38).
- `state-ref`는 올리지 않는다. 코어 소스는 `main`과 같고, 일곱 패키지의 peer `state-ref ^3.1.0`을 npm의 3.2.0이 만족한다.

**순서:** sync를 먼저 올린다. 커넥터 6종의 선택적 peer는 `^0.3.0`이라, 0.3.0이 npm에 없을 때 커넥터와 sync를 함께 설치하면 sync 0.2.0이 peer 범위에 맞지 않는다. 사이트는 병합하자마자 커넥터와 함께 `@stateref/sync` 설치를 안내한다. 2~7번끼리는 서로 의존하지 않아 순서가 상관없다.

## 배포 전에 알고 있어야 할 것

- **sync 0.3.0의 깨질 수 있는 변경.** 자세한 내용과 이전 방법은 CHANGELOG의 Changed에 있다.
  - query key 안의 state-ref ref는 `TypeError`를 던진다. key를 해시하는 모든 API(`query`, `fetch`, `prefetch`, `ensure`, `invalidate`, `remove`, `hashQueryKey` 등)가 해당한다. 전에는 `{}`로 해시되어 모든 id가 한 항목을 조용히 공유했다. 이전 방법: `['user', idRef.value]`처럼 값을 넣는다.
  - `MutationLink.query`, `StageLinkedMutationLink.query`, `PersistedLinkedMutation.send(queries)`가 `QueryHandleCore<any>`를 받는다. 넘기는 쪽은 넓어졌지만(`q.handle()`도 넣을 수 있다), link에서 `dispose`·`display`·`watchDisplay`를 읽거나 명시 타입으로 이 타입을 구현한 코드는 컴파일되지 않는다. 이전 방법: 자기가 가진 핸들에서 읽는다.
  - `QueryDisplayRef`는 값이 없는 경로 아래도 연다. `display.data.name.value`가 타입 오류 대신 `string | undefined`이고, nullable·optional 필드 아래 leaf에 `| undefined`가 붙는다. 런타임은 그대로다.
- **병합하면 문서 사이트가 바로 배포된다.** `main`에 `stateRefDocs/**` 변경이 푸시되면 `.github/workflows/deploy-docs.yml`이 사이트를 배포한다. 그때부터 사이트가 `./sync`와 `@stateref/connect-lithent`를 안내하므로, 게시 전까지 그 안내대로 하면 설치나 import가 실패한다. 그래서 오래 걸리는 검사는 1절에서 병합 전에 끝내고, 병합한 뒤에는 바로 빌드하고 게시한다.
- **Lithent CommonJS.** 공개 `lithent@1.24.0`은 `require`를 `type: module` 안의 `.umd.js`에 지정해 Node에서 빈 namespace(`mount`·`useRenew` 없음)를 돌려준다([superlucky84/lithent#92](https://github.com/superlucky84/lithent/issues/92)). 그래서 `@stateref/connect-lithent`는 두 진입점 모두 ESM 전용이고 `require`를 `ERR_PACKAGE_PATH_NOT_EXPORTED`로 거절한다(DC-QH-38). 다섯 커넥터의 `./sync`도 ESM 전용이며, 기본 진입점의 CommonJS는 그대로다. 2026-10-09 npm의 `lithent@1.24.1`은 `require`를 `.cjs`로 지정하지만, 커넥터는 `lithent@1.24.0`과 `lithent-concurrent@0.1.3`으로만 검증했다(npm에는 0.1.4도 있다). peer `^1.24.0`이면 새 설치는 1.24.1을 받는다. CommonJS 진입점 추가는 이번 범위가 아니다.
- **AI 스킬.** 이 브랜치의 `skills/state-ref` 변경은 `state-ref` 패키지의 `dist/skills`로 배포된다(`scripts/copy-skills.mjs`). `state-ref`는 올리지 않으므로 npm의 3.2.0 스킬에는 컴포넌트 조회가 없다. 함께 내보내려면 3.1.1처럼 문서만 바뀐 patch를 따로 정한다.
- **사람의 평가.** [MANUAL_TEST_CHECKLIST](../sync-query-hooks/MANUAL_TEST_CHECKLIST.md)의 M-QH-01~07은 자동 브라우저 검증으로 통과했다. 사람이 볼 사용성·실제 기기 두 항목은 미수행이다.

## 8. GitHub 릴리스

```bash

section "@stateref/connect-lithent 0.1.0" > "$notes/lithent.md"
```
