# 2026-10-08 배포 절차 — `state-ref` 3.2.0

`feat/shared-store` 브랜치(번들 간 공유 진입점 `state-ref/shared`)를 `main`에 병합한 뒤 이 문서의 명령을 위에서부터 차례로 실행한다. 전체 흐름과 문제 대처는 [2026-09-30 배포 절차](./2026-09-30.md), [2026-10-03 배포 절차](./2026-10-03.md)와 같고, 여기서는 이번에 달라지는 부분만 적는다.

준비 상태(브랜치에 커밋됨, **아직 배포하지 않음**):

- `packages/state-ref/package.json` 3.1.1 → **3.2.0**.
- `CHANGELOG.md`에 `state-ref 3.2.0` 절을 넣었다.
- AI 스킬에 `reference/shared-across-bundles.md`를 추가했고, `SKILL.md`·`core-rules.md`·agent add-on에 항목을 넣었다.
- 브랜치에서 `pnpm gate`(21단계), `pnpm check:packaging`, `pnpm test:e2e`(103개)가 PASS. `dist`의 스킬과 add-on에 버전 3.2.0이 주입됐다. publish dry run 결과는 아래 4절에 있다.

## 버전을 3.2.0으로 정한 이유

새 진입점 `state-ref/shared`가 추가됐고 기존 API와 동작은 바뀌지 않았다. 기능 추가이면서 하위 호환이므로 minor를 올린다. `state-ref`만 import하는 앱의 코어 번들은 3.1.1과 같은 크기다(게이트의 `bundle` 단계: 3,727 B gzip).

## 무엇을 올리나

| 패키지 | npm에 있는 버전 | 올릴 버전 | 성격 |
|---|---|---|---|
| `state-ref` | 3.1.1 | **3.2.0** | 기능 추가: `state-ref/shared` (`ensureShared`, `provideShared`, `sharedWatch`, `isProvided`, `isReady`, `whenReady`, `getShared`, `onShared`, `pendingShared`). 3.1.x 코드는 그대로 동작한다. |

`@stateref/sync`와 커넥터 5종은 소스가 바뀌지 않았으므로 올리지 않는다. 이 패키지들의 peer는 `state-ref ^3.1.0`이라 3.2.0과 함께 설치된다. 이번에 추가한 것은 테스트 파일뿐이다(`packages/sync/src/tests/shared.test.ts`, `packages/connect-preact/src/tests/preact/shared.tsx`).

## 배포 전에 알고 있어야 할 것

[IMPLEMENT](../shared-store/IMPLEMENT.md)에 미완료로 남아 있는 항목이다. 배포를 막을지는 판단이 필요하다.

- 서로 다른 state-ref **버전**을 담은 번들의 조합은 실행해 보지 않았다. 같은 버전을 각자 품은 두 번들은 실제 번들러로 따로 빌드해 실제 Chromium에서 확인했다(`pnpm test:e2e`의 `shared/*` 3개).
- sync 클라이언트를 사본이 다른 번들에서 받아 query·mutation을 실행하는 것은 같은 E2E로 확인했다. 소비 쪽의 state-ref 값을 클라이언트에 넘기는 경우(반응형 query key, `links`)와 동시 load의 중복 제거는 사본이 다른 번들에서 확인하지 않았다.
- 공유 watch와 커넥터의 조합은 Preact만 테스트했다.
- 수동 검증 [M-SH-01·02](../shared-store/MANUAL_TEST_CHECKLIST.md)는 E2E로 자동화한 항목이 통과했고, 사람이 봐야 하는 항목 세 개와 M-SH-04(가이드 읽기)는 미수행이다.
