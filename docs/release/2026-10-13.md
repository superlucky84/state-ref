# PR #19 배포 — state-ref 3.2.2, sync 0.3.1, Lithent 커넥터 0.2.0

PR [#19](https://github.com/superlucky84/state-ref/pull/19)의
`fix/issue-18-shared-sync` 브랜치에서 버전과 문서를 준비한다. 사용자는 PR을
병합한 뒤 아래 명령으로 npm에 게시한다. npm 게시와 Git 태그 생성은 준비
작업에 포함하지 않는다. main 병합은 문서 사이트의 자동 배포를 시작한다.

| 게시 순서 | 패키지 | npm 현재 버전 (2026-10-13 확인) | 준비한 버전 |
| --- | --- | --- | --- |
| 1 | `state-ref` | 3.2.1 | **3.2.2** |
| 2 | `@stateref/sync` | 0.3.0 | **0.3.1** |
| 3 | `@stateref/connect-lithent` | 0.1.0 | **0.2.0** |

다른 다섯 커넥터는 게시하지 않는다. peer 범위도 유지한다. 이전 배포 문서
`2026-10-09.md`의 여덟 패키지 게시 명령은 이번 릴리스에 사용하지 않는다.

## 변경과 이전 방법

- `state-ref 3.2.2`: helper ref를 값을 읽지 않고 식별하는 심볼, draft 예약 키,
  수정된 AI 스킬과 agent add-on.
- `@stateref/sync 0.3.1`: helper ref query key 거절과 editable payload 예약 키.
  완전한 helper-ref 검사는 state-ref 3.2.2와 sync 0.3.1을 함께 사용한다.
  구버전 helper ref의 기존 한계는 유지되며 CHANGELOG에 설명되어 있다.
- `@stateref/connect-lithent 0.2.0`: `createSyncQuery`가 직접 readonly display
  ref를 반환한다. `account().data.name.value`를
  `account.data.name.value`로 바꾼다. 저장한 하위 ref도 현재 key를 따른다.
  0.x minor를 올려 기존 `^0.1.0` 설치에 자동으로 적용되지 않게 한다.

## 준비 검증

2026-10-13 준비 검증은 다음과 같이 통과했다. main 병합과 npm 게시는
사용자가 이어서 수행한다.

- frozen lockfile 설치, 새 루트 build와 docs build 통과. AI 스킬과 agent
  add-on 버전 3.2.2 확인.
- `pnpm gate --quick` 통과: workspace 테스트 1,178 통과·기존 concurrent 전용
  2 제외, 별도 SSR 15 통과, 타입·lint·문서 예제·번들 검사 통과.
- quick에서 제외한 공개 packaging 검사 별도 통과. 정확한 Lithent README/site
  예제의 조회·편집·refetch·invalidate·linked save·SSR 실행 포함.
- Lithent concurrent DOM 24/24, concurrent SSR 5/5 통과.
- 성능 6/6, core 최소 번들 3,754 B gzip (상한 3,800 B) 통과.
- 세 패키지 게시 dry run 통과: state-ref 94 파일·192.4 kB,
  sync 24 파일·58.3 kB, connect-lithent 11 파일·7.8 kB.
- `pnpm pack`으로 만든 세 tarball의 이름·버전·workspace 프로토콜 치환 확인.
  core tarball의 AI 안내문 버전과 직접 Lithent ref 사용도 확인.
- 변경한 사이트 페이지의 prettier와 `git diff --check` 통과.

이번 준비에서 라이브러리 런타임 코드는 추가로 바꾸지 않았다. 버전 준비 전
PR #19 리뷰에서 Chromium 공유 bundle 15/15와 Lithent base/concurrent mission
16/16을 통과했으며, 이번 준비에서 전체 65개 mission이나 framework version
matrix를 다시 실행한 결과로 표시하지 않는다.

재현 명령(저장소 루트, pnpm 9.12.3, Volta의 Node 24.11.1):

```bash
volta run --node 24.11.1 pnpm install --frozen-lockfile
volta run --node 24.11.1 pnpm build
volta run --node 24.11.1 pnpm gate --quick
volta run --node 24.11.1 pnpm check:packaging
LITHENT_CORE=concurrent volta run --node 24.11.1 pnpm --filter @stateref/connect-lithent test
LITHENT_CORE=concurrent volta run --node 24.11.1 pnpm --filter @stateref/connect-lithent test:ssr
git diff --check
```

`--quick`은 직전의 새 루트 build를 사용한다. quick에서 제외한 packaging은
별도로 실행한다. 루트 build는 선언 파일을 보정하고 버전 3.2.2를 주입한
AI 스킬과 agent add-on을 배포물에 복사한다.

## 병합 후 게시

각 명령이 성공한 뒤 다음 명령을 실행한다. 다음 명령은 저장소 루트에서
실행한다. main에 준비한 세 버전이 들어 있어야 한다.

```bash
git switch main
git pull --ff-only origin main
git status --short

volta run --node 24.11.1 pnpm install --frozen-lockfile
volta run --node 24.11.1 pnpm build
npm whoami
```

`git status --short` 출력은 비어 있어야 한다. `npm whoami`가 실패하면
`npm login`으로 로그인한 뒤 다시 확인한다. npm이 요구하는 게시 인증을
완료한다. 병합 뒤 다른 코드가 함께 바뀌었다면 준비 검증을 다시 실행한다.

게시물 이름과 버전을 확인하는 dry run:

```bash
(cd packages/state-ref && volta run --node 24.11.1 pnpm publish --dry-run --access public --publish-branch=main)
(cd packages/sync && volta run --node 24.11.1 pnpm publish --dry-run --access public --publish-branch=main)
(cd packages/connect-lithent && volta run --node 24.11.1 pnpm publish --dry-run --access public --publish-branch=main)
```

위 표의 순서대로 실제 게시한다. 각 `npm view`가 예상 버전을 보이면 다음
패키지로 넘어간다.

```bash
(cd packages/state-ref && volta run --node 24.11.1 pnpm publish --access public --publish-branch=main)
npm view state-ref version
# 3.2.2

(cd packages/sync && volta run --node 24.11.1 pnpm publish --access public --publish-branch=main)
npm view @stateref/sync version
# 0.3.1

(cd packages/connect-lithent && volta run --node 24.11.1 pnpm publish --access public --publish-branch=main)
npm view @stateref/connect-lithent version
# 0.2.0
```

## 게시 뒤 기록

세 패키지 게시 성공 뒤 그 소스를 가리키는 태그를 생성한다.

```bash
git tag "state-ref@3.2.2"
git tag "@stateref/sync@0.3.1"
git tag "@stateref/connect-lithent@0.2.0"
git push origin "state-ref@3.2.2" "@stateref/sync@0.3.1" "@stateref/connect-lithent@0.2.0"

gh run list --workflow deploy-docs.yml --limit 3
```

GitHub Actions의 `Deploy docs site`가 `completed / success`인지 확인한다.
사이트는 별도 수동 게시 명령 없이 main 병합으로 갱신된다.

GitHub 릴리스도 만들 경우:

```bash
section() { awk -v h="## $1" '$0==h{f=1;next} /^## /{f=0} f' CHANGELOG.md; }
pr19_notes=$(mktemp -d)
section "state-ref 3.2.2" > "$pr19_notes/state-ref.md"
section "@stateref/sync 0.3.1" > "$pr19_notes/sync.md"
section "@stateref/connect-lithent 0.2.0" > "$pr19_notes/lithent.md"
gh release create "state-ref@3.2.2" --verify-tag --title "state-ref 3.2.2" --notes-file "$pr19_notes/state-ref.md"
gh release create "@stateref/sync@0.3.1" --verify-tag --title "@stateref/sync 0.3.1" --notes-file "$pr19_notes/sync.md"
gh release create "@stateref/connect-lithent@0.2.0" --verify-tag --title "@stateref/connect-lithent 0.2.0" --notes-file "$pr19_notes/lithent.md"
```

게시 완료 후 병합 SHA, npm 게시 버전·시각, 태그와 문서 배포 결과를 기록한다.
