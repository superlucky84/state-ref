# 2026-10-03 배포 절차 — `@stateref/sync` 0.2.0, `state-ref` 3.1.1

PR #14(`ccr-f71cbd04-cgvi9s` → `main`, 서버 push 스트림 `streamQuery`)를 병합한 뒤 이 문서의 명령을 위에서부터 차례로 실행한다. 전체 흐름과 문제 대처는 [2026-09-30 배포 절차](./2026-09-30.md)와 같고, 여기서는 이번에 달라지는 부분만 적는다.

준비 상태(브랜치에 커밋됨):

- `packages/sync/package.json` 0.1.0 → **0.2.0**, `packages/state-ref/package.json` 3.1.0 → **3.1.1**.
- `CHANGELOG.md`에 `@stateref/sync 0.2.0`과 `state-ref 3.1.1` 절을 넣었다. `(unreleased)` 표시는 없다.
- AI 스킬 `server-sync.md` 제목을 `@stateref/sync 0.2`로 바꿨고, agent add-on에 스트리밍 항목을 추가했다.
- 브랜치에서 `pnpm install --frozen-lockfile`, `pnpm gate`(19단계), `pnpm check:packaging`이 PASS. `dist`에 스킬과 add-on 버전 3.1.1이 주입됐다. 두 패키지의 publish dry run 결과는 아래 4절의 표에 있다.

## 무엇을 올리나

| 순서 | 패키지 | npm에 있는 버전 | 올릴 버전 | 성격 |
|---|---|---|---|---|
| 1 | `state-ref` | 3.1.0 | **3.1.1** | **문서만 바뀜.** 패키지에 들어 있는 AI 스킬과 agent add-on이 sync 0.2 스트리밍을 설명한다. 코드는 3.1.0과 같다. |
| 2 | `@stateref/sync` | 0.1.0 | **0.2.0** | 기능 추가: `streamQuery`, `ndjsonMessages`, `webSocketMessages`, `QueryHandle.serverValue()`, 관련 타입. 0.1.0 코드는 그대로 동작한다. peer는 `state-ref ^3.1.0` 그대로다. |

커넥터 5종은 바뀌지 않았으므로 올리지 않는다.

**순서:** sync의 peer는 `^3.1.0`이라 3.1.1이 없어도 설치된다. 따라서 기술적으로는 순서가 상관없다. 다만 지난번처럼 코어를 먼저 올린다. 3.1.1을 올리지 않기로 하면 1번만 건너뛰고, `packages/state-ref/package.json`을 3.1.0으로 되돌리고 CHANGELOG의 3.1.1 절을 지운다. 버전 증가 없이 다시 올릴 수는 없다.

## 7. 태그


## 8. 문서 사이트 배포 (gh-pages)

사이트는 `gh-pages` 브랜치 루트의 `index.html`·`assets/`·`stateref.png`로 서비스된다(vite `base: '/state-ref/'`). 사이트 빌드는 `emptyOutDir: false`라서 예전 asset이 `dist`에 남을 수 있다. 지난 배포 커밋(`6809636`)에는 e2e 결과와 vite 임시 파일도 함께 들어갔다. 그래서 `dist`를 비우고 필요한 세 가지만 커밋한다.

```bash
rm -rf stateRefDocs/dist
pnpm build:docs
git fetch origin gh-pages
git worktree add ../state-ref-gh-pages -B gh-pages origin/gh-pages
cd ../state-ref-gh-pages
git rm -rq assets
cp -r ../state-ref/stateRefDocs/dist/assets ../state-ref/stateRefDocs/dist/index.html ../state-ref/stateRefDocs/dist/stateref.png .
git add index.html assets stateref.png
git status --short          # index.html, assets/*, (바뀌었다면) stateref.png만 있어야 한다
git commit -m "docs site: streaming guide (@stateref/sync 0.2.0)"
git push origin gh-pages
cd ../state-ref && git worktree remove ../state-ref-gh-pages
```

반영 확인(몇 분 걸릴 수 있다): https://superlucky84.github.io/state-ref/#/guide/sync-stream 과 `#/ko/guide/sync-stream`이 열리고, 사이드바의 서버 동기화 섹션에 "Streaming/스트리밍"이 보여야 한다.
