# 문서 사이트 수동 확인 목록

상태: 2026-09-28. **전부 미수행.** 자동으로 확인한 것(빌드·링크 해소·시그니처 대조)은 [IMPLEMENT](./IMPLEMENT.md)에 있고, 이 문서는 **사람이 브라우저에서 봐야 하는 것**만 담는다.

```bash
pnpm dev:docs        # 개발 서버
pnpm --filter state-ref-docs build   # 빌드만 확인
```

미수행을 통과로 바꾸지 않는다. 실패에는 재현 절차·브라우저·커밋 SHA를 적는다.

## M-DS-01 — 사이드바와 도달성

- [ ] 새 섹션 둘(`Local Draft`·`Server Sync`)이 사이드바에 보이고 펼쳐진다.
- [ ] 두 섹션의 모든 항목과 API Reference의 새 항목 셋을 눌러 각 페이지가 열린다(11 + 3 = 14개).
- [ ] 현재 보고 있는 페이지의 사이드바 항목이 활성 표시된다.
- [ ] 언어를 바꿔도 같은 페이지에 머문다(`/guide/sync-query` ↔ `/ko/guide/sync-query`).

**합격:** 새 페이지 전부가 사이드바만으로 도달 가능하고, 언어 전환이 페이지를 잃지 않음.

## M-DS-02 — 페이지 렌더

- [ ] 새 15장(en) + 15장(ko)에 깨진 마크업이나 빈 절이 없다.
- [ ] 모든 `CodeBlock`이 하이라이트된다 — 특히 `vue`·`html`(Svelte)·`bash` 블록.
- [ ] 코드 블록에 가로 스크롤이 필요한 줄이 있어도 페이지 전체가 가로로 밀리지 않는다.
- [ ] 콘솔에 오류·경고가 없다.

**합격:** 새 페이지가 기존 페이지와 같은 품질로 렌더됨.

## M-DS-03 — 링크

- [ ] 각 페이지 끝 `Related`(ko: `관련 문서`)의 링크가 전부 열린다.
- [ ] 한국어 페이지의 링크가 한국어 페이지로 간다(`#/ko/...`).
- [ ] README의 목차 링크를 표본으로 눌러 본다 — 배포된 사이트에서 해시가 실제로 동작하는지(로컬 dev 서버가 아니라 **GitHub Pages에서**).

**합격:** 내부·외부 링크가 의도한 언어의 의도한 페이지로 감. 자동 검사는 라우트 존재만 보고 **배포 URL은 보지 않는다.**

## M-DS-04 — 반응형과 테마

- [ ] 좁은 폭(모바일)에서 사이드바가 접히고 본문이 읽힌다.
- [ ] 다크 모드에서 코드 블록과 표가 읽힌다.
- [ ] 새로 넣은 표(`Packages` 표는 README, 사이트에는 없음 / `Sync API`의 목록 등)가 좁은 폭에서 깨지지 않는다.

**합격:** 새 페이지가 기존 페이지와 같은 반응형·테마 동작을 가짐.

## M-DS-05 — 내용 점검 (사용자)

자동으로 판정할 수 없고 사람이 읽어야 하는 것들이다.

- [ ] 한국어판의 문체가 어색하지 않다.
- [ ] `Server Sync` 개요의 **범위와 한계** 절이 과장도 축소도 아니다.
- [ ] `Plugin API`의 첫 문단(이 표면이 무엇이고 무엇이 아닌지)이 의도와 맞다.
- [ ] 루트 README의 `Why` 다섯 줄이 실제 장점을 말하고 있다.

**합격:** 사용자가 읽고 수정 요청이 없거나, 나온 요청을 반영함.

## M-DS-06 — 배포

- [ ] `pnpm build:docs` 결과가 GitHub Pages에 올라가고 `https://superlucky84.github.io/state-ref/#/`가 새 사이드바를 보여 준다.
- [ ] 새 라우트를 직접 URL로 열어도 동작한다(해시 라우터이므로 서버 설정이 필요 없어야 한다).

**합격:** 배포본에서 새 문서에 도달 가능.
