state-ref 번들 조합 예제

선택적 helper 조합과 의존성 경계를 손으로 확인하는 페이지들이다 (수동 체크리스트 M2-01).

이 목록은 개발 서버(pnpm --filter stateref-example-bundles dev, 기본 5186 포트)용이다. 프로덕션 빌드는 조합마다 별도 디렉터리로 나가므로 아래 링크가 이어지지 않는다.

ESM 조합

  • core 단독 — 두 helper도 서버 엔진도 없다.
  • core + draft — 로컬 draft만. 네트워크 구현이 없다.
  • core + sync — 조회·편집·mutation. draft를 필수로 가져오지 않는다.
  • 전체 조합 — core·draft·batch·sync를 함께 쓴다.

UMD script 태그 조합

  • core 단독
  • core → draft
  • core → batch
  • draft만 로드 (코어 누락 오류)

UMD 파일은 packages/*/dist의 실제 산출물을 /vendor/로 그대로 제공한다. 먼저 pnpm build를 실행해야 한다.

따로 빌드한 번들의 공유 (state-ref/shared)

  • 제공 번들 먼저
  • 소비 번들 먼저
  • 제공 번들을 나중에 로드
  • 다른 번들의 클라이언트로 observer와 훅 사용
  • sync 0.2 클라이언트 먼저
  • sync 0.3 클라이언트 먼저

제공 번들과 소비 번들은 각각 따로 빌드되어 자기 몫의 state-ref와 @stateref/sync 사본을 품는다. observer와 훅 페이지는 세 번들을 따로 빌드한다. 이 페이지들은 pnpm build:examples의 산출물로만 열리고 (dist/shared), pnpm dev에서는 열리지 않는다. pnpm test:e2e가 실제 브라우저에서 확인한다.

자동 검사와의 관계

pnpm check:examples가 네 ESM 진입점을 각각 빌드하고 각 진입점의 해석된 모듈 그래프를 기록해 경계를 단언한다 (DC8-5-08). 자동 검사는 이 페이지들이 브라우저에서 실제로 동작한다는 증거가 아니다 — 그 확인이 M2-01이다.
